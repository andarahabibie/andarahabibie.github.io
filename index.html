AI-Redact

In development at the Constitutional Court ICT Center

A web service that finds personal data in legal documents and removes it from the file. Editors review every finding before the system redacts.

  • Detects 18 types of personal data: names, NIK, phone numbers, addresses, bank accounts, NPWP, BPJS, API keys, and more.
  • Reads PDF, TXT, PNG, JPG, DOCX, and XLSX files. Scanned pages go through OCR.
  • Combines Hyperscan regex rules with an IndoBERT NER model (INT8, ONNX). An Indonesian legal term dictionary cuts false name matches.
  • Protects files with Google sign-in (OAuth2 + PKCE), per-user ownership checks, CSRF checks, and automatic deletion one hour after upload.
PythonFastAPICeleryRedisONNX RuntimeDocker ComposeNginx

Source on GitHub

  1. Extract

    Reads text and page layout. Runs OCR on scanned pages.

  2. Detect

    Regex rules and IndoBERT NER mark candidate personal data with bounding boxes.

  3. Review

    An editor accepts, rejects, or adds findings in the browser.

  4. Redact

    Removes the text from the PDF, image, DOCX, or XLSX file itself.

  5. Verify

    Checks that the removed text cannot be copied or found with Ctrl+F.

Status: unit tests pass. Load tests, security tests, and end-to-end tests with Docker, Redis, and Google OAuth come before go-live.

2026 Thesis

Extractive Summarization for LPP TVRI

Final year thesis, Budi Luhur University

A transparent NLP pipeline that summarizes Forum Reformasi Birokrasi meeting minutes. It fuses BM25, position, length, and keyword scores with LSA/SVD, then picks sentences with MMR. ROUGE evaluation sits inside the interface. ROUGE-1 F1 is 0.3665, ROUGE-2 F1 is 0.1840, and ROUGE-L F1 is 0.2261.

I also compared it with TextRank on 7 documents. TextRank scored 0.2194 and LSA scored 0.2070 in macro ROUGE F1. A paired t-test gave p = 0.45, so the gap is not significant.
